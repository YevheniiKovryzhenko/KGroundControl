# Native Qt SDK for Ubuntu

`install_Qt.sh` defaults to Qt **6.12.0**, static release libraries, and `$HOME/Qt/Static/v6.12.0/install`. Run as your normal user:

```bash
./install_Qt.sh --jobs 8
# For unattended use, after reviewing Qt's open-source license terms:
./install_Qt.sh -y --jobs 8
# An older Qt 6 release uses a separate version directory:
./install_Qt.sh --version 6.10.2
```

The package list targets Ubuntu 24.04. Other Ubuntu releases may need different package names or newer tools. Apt installs dependencies, without upgrading the whole system. Some packages require Ubuntu's Universe repository to be enabled. `--no-deps` uses an already prepared machine. `--creator` installs Ubuntu's Qt Creator separately; Qt Creator is not part of the Qt SDK build. `--help` lists options. Additional Qt configure arguments follow `--`.

The script initializes **all** release submodules rather than the smaller `default` set. Qt selects modules supported by the host and available dependencies. Examples and tests are omitted, accessibility remains enabled, and XCB and OpenSSL support are required. Broad dependencies cover graphics, Wayland, multimedia, Bluetooth, SQL drivers, speech, and Protobuf/gRPC. Availability and version checks in the selected Qt release still decide which optional features are built. This does not guarantee every module or backend: platform-specific modules, commercial-only sources, missing/new dependencies and incompatible module combinations remain subject to Qt's configuration rules. Inspect `build/config.summary`, configure output in `logs/`, and `installed-modules.txt`. QDoc may require a newer libclang than an older Ubuntu distribution provides. Documentation is not generated by this script.

**WebEngine exception:** static Qt WebEngine is unsupported. The default excludes the `qtwebengine` repository, which also contains Qt PDF. To include those sources in a separate shared SDK, use:

```bash
./install_Qt.sh --shared --with-webengine
```

WebEngine has additional release-specific compiler, Python, Node.js and RAM requirements. This is a much larger build; consult the selected release's [platform notes](https://doc.qt.io/qt-6/qtwebengine-platform-notes.html).

A static Qt SDK does **not** produce a fully static Linux executable: system libraries may remain dynamically linked. OpenSSL is deliberately loaded at runtime (`-openssl-runtime`) through the OpenSSL backend plugin; deploy a compatible system OpenSSL runtime with the application.

## Retries and existing installations

Sources, builds and installs are retained, with no automatic `rm`, reset or clean. Re-running with identical settings reconfigures and performs an incremental build/install, even after interruption. A lock prevents concurrent runs on the same SDK. The script checks source release commits and tracked modifications, retains logs and a source commit inventory, and refuses an incompatible existing CMake cache. Do not run it concurrently with manual edits/builds of the same SDK.

If configuration inputs change or a build came from the previous installer, use a fresh `--root /absolute/path` or manually relocate the old `build` **and** `install` directories first. Do not overlay a changed module selection onto an old install prefix: removed modules could leave stale package files. Package/compiler upgrades can also warrant a fresh build. No checkpoint can prove that every external dependency is unchanged.

After installation a generated consumer project configures and links Core, Gui, Widgets, Network, SerialPort, and Location, checks the XCB and OpenSSL plugin targets, and verifies static Core for the default build. It does not launch a GUI, exercise TLS, or replace application-specific build/runtime tests.

## Using the SDK in projects

Select the SDK explicitly when configuring a fresh CMake build directory:

```bash
cmake -S /path/to/project -B /path/to/project/build-qt-6.12.0 \
  -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH="$HOME/Qt/Static/v6.12.0/install"
cmake --build /path/to/project/build-qt-6.12.0 --parallel 8
```

Projects with custom Qt discovery may require their own SDK selection setting. The same installation can be reused across projects with compatible toolchains.
